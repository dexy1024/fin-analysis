# 快照 CSV 中的「实际交易动作」说明

本文说明 `logs/snapshots_hs300_YYYY.csv` 与 `logs/snapshots_YYYY*.csv` 中**同一套表头**下，字段 **「实际交易动作」** 的含义与判定规则。两类文件均由作战指令快照引擎写入，HS300 仅标的池不同，**本列逻辑一致**。

---

## 一、取值（仅三种）

| 取值 | 含义 |
|------|------|
| **买入** | 下面「买入」四条**全部**成立。 |
| **卖出** | 下面「卖出」四条**全部**成立。 |
| **观望** | 买入四条与卖出四条**均未**同时成立（缺任意一条即观望）。 |

**判定顺序**（与代码一致）：先判断是否满足 **买入** 四条件，满足则直接为「买入」；否则再判断是否满足 **卖出** 四条件，满足则为「卖出」；否则为「观望」。

**客观缠论信号串**：用子串判断。**买入**要求文案中**含「买」且不含「卖」**（如仅「二买」「一买+二买」）；若出现「二卖+二买」等**同时含买、卖**，则**不满足**买入第一条，不会因「有买」而走买入分支（决策理由中会写「同时含买、卖，不满足仅买无卖」）。**卖出**仍要求文案中含 **「卖」**（当前实现未要求「无买」，与买入不对称）。

---

## 二、60m 笔方向是怎么来的（与「实际交易动作」共用同一套 60m 笔）

CSV 里的 **「60m笔方向」** 只有 **「向上」** 或 **「向下」**，与「实际交易动作」里第 2 条条件用的是**同一结论**：都看 **60 分钟最后一根「有效笔」** 的方向。

### 1. 数据从哪来

引擎对标的调用 `get_index_kline(..., period="60")`（只读本地缓存时仍是一套缠论计算结果）。返回里带 **`pens_effective`**（有效笔列表），后续状态机与快照列都基于它。

### 2. 笔是怎么算出来的（`indicators.py`）

对 60m K 线序列（先做标准化合并等）：

1. **`_find_fractals_from_standardized`**：得到顶 / 底分型。  
2. **`_build_bi_from_fractals`**：按缠论笔规则，相邻且类型交替的分型连成笔：  
   - 底分型 → 顶分型：**向上笔**，内部 `direction` 记为 **`"up"`**；  
   - 顶分型 → 底分型：**向下笔**，`direction` 记为 **`"down"`**；  
   - 两分型之间在原始序列上须间隔足够（至少隔 1 根独立 K，与实现一致）。  
3. **`_normalize_effective_pens`**：**有效笔**——要求笔**方向交替**；若出现连续同向笔，则合并为更极端的一根（向上笔取更高的终点价，向下笔取更低的终点价），得到最终的 **`pens_effective`**。

### 3. 「向上 / 向下」如何落到 CSV（`trade_command_engine.py` + `csv_logger.py`）

- **`_compute_h60_conditions`** 里：`last_pen_up = (pens_effective[-1]["direction"] == "up")`，即**最后一根有效笔**是否为向上（英文内部存 `"up"` / `"down"`）。  
- **`build_snapshot_data` → `_pen_direction(analysis)`**：  
  - `last_pen_up` 为真 → CSV **「60m笔方向」** 填 **「向上」**；  
  - 否则 → **「向下」**。  

若 **`pens_effective` 少于 2 根**，不更新 `last_pen_up`（保持默认假），列上会为 **「向下」**——表示**当前无法用「最后一笔」可靠标定向上**，属于数据不足时的回落，并非另行一套方向算法。

---

## 三、买入（满仓出击条件集）：四条须同时满足

1. **客观缠论信号（60m）** 文案中含 **「买」**且**不含「卖」**（一买、二买、三买及「+」连接的组合须**全部为买点用语**，不得出现卖类字样；「二卖+二买」不符合本条）。  
2. **60m 笔方向** 为 **「向下」**（见上节：最后一根有效笔 `direction == "down"`）。  
3. **15分信号** 为 **「底背驰」**（由 15m K 线、有效笔、MACD 绿柱面积 / DIF 极值、同向前一笔对比、笔端底分型等独立计算；不满足则一般为「无信号」）。  
4. **区间价格对齐** 为 **「是」**：仅在「15 分为底背驰」且「60m 笔为向下」时才有意义——取 15m 侧触发底背驰的向下笔最低价，与 60m 当前向下笔最低价比较，**绝对值差 ≤ 0.01** 为「是」，否则为「否」。若 15 分为「无信号」，该列一般为 **「-」**，本条不成立，整体为观望。

---

## 四、卖出（鸣金收兵条件集）：四条须同时满足

1. **客观缠论信号（60m）** 文案中含 **「卖」**。  
2. **60m 笔方向** 为 **「向上」**（最后一根有效笔 `direction == "up"`）。  
3. **15分信号** 为 **「顶背驰」**（与底背驰对称：向上笔、红柱面积与 DIF、顶分型等同理）。  
4. **区间价格对齐** 为 **「是」**：仅在「15 分为顶背驰」且「60m 笔为向上」时——15m 触发笔最高价与 60m 当前向上笔最高价之差的**绝对值 ≤ 0.01** 为「是」，否则为「否」。15 分无背驰时对齐常为 **「-」**，本条不成立。

---

## 五、「决策理由」列

未凑齐四条件时，**决策理由** 会文字概括缺哪类条件（如 15 分无背驰、区间价格对齐为「-」/「否」等），可与本列对照。

---

## 六、代码位置

| 模块 | 函数 / 要点 |
|------|-------------|
| `backend/services/indicators.py` | `_find_fractals_from_standardized`、`_build_bi_from_fractals`、`_normalize_effective_pens`；`get_index_kline` 组装 `pens_effective`。 |
| `backend/services/trade_command_engine.py` | **`_compute_h60_conditions`**：计算 `last_pen_up` 等。 |
| `backend/utils/csv_logger.py` | **`_pen_direction`**：输出「60m笔方向」；**`_to_chinese_trade_signal`**：输出「实际交易动作」；**`_price_alignment`**：区间价格对齐；**`_h15_signal`** / **`_h15_signal_detail`**：15 分背驰文案。 |

---

## 七、使用注意

- 本列由引擎根据**本地已落盘**的日线 / 60m / 15m 数据计算，**不代表**已下单或实盘指令；以记录与复盘为主。  
- CSV 若含批次间空行，下游解析时应跳过空行或按空行分段。
